WHAT IT IS

An accountant for your agents,
not another dashboard.

Token Budget watches the one number your agent stack actually burns — tokens — and makes every decision from facts instead of estimates.

01
⌂

Local, private ledger

Usage lands in a SQLite ledger on your disk. Codex and Claude Code session records are ingested with replay-safe dedupe and separated into factual categories: input, cached input, cache creation, output, reasoning.

02
◉

Deterministic gates

normal, efficient, conserve, stop. Identical inputs produce identical decisions. Stale or missing usage fails closed with DENY_USAGE_UNAVAILABLE — never a quiet estimate.

03
↗

Auditable by construction

Plans, revisions, per-window reservations, and decisions chain into an append-only hash. The final receipt is derived evidence, not a promise.

HOW IT WORKS

From clone to controlled spend
in three steps.

1

Ingest the facts

Point it at ~/.codex/sessions and ~/.claude/projects. Replays dedupe; every category is kept factually.

2

Gate every call

plan checks reserves against live windows and returns a full schedule, needs_clarification, or infeasible — it never invents phases. Over budget or out of data means deny.

3

Issue the receipt

receipt emits per-model factual tokens, remaining balances, and deterministic seconds until both windows reset.

GOOD TO KNOW

Questions, answered.

Does anything leave my machine?

No cloud calls, no accounts. The ledger is a local SQLite file, and ingestion reads your provider's own session records off disk. What gets stored is factual usage metadata — never prompts, responses, or code.

Is a subscription percentage the same as a token count?

No. Factual tokens and subscription window percentages are handled separately. Percentages enter only with a sourced, timestamped calibration from the provider — never converted from token math, never back-filled from text length.

Will it actually stop my agent?

The protocol returns DENY when a window is out of room or its data is stale, and the agent treats that as an absolute stop. For a hard technical block you need an enforcing host: the optional codex-managed launcher for Codex, or your own hook, wrapper, or proxy. It never claims a cap it can't enforce.

What happens when usage data goes stale?

Fail-closed: the gate returns DENY_USAGE_UNAVAILABLE instead of guessing. Never estimating missing factual usage from text length is a rule, not a fallback.
